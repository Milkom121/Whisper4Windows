# Disegno completo: docs/fondamenta/sistema-aggiornamento-metodo.md
#
# REGOLE DI FORMATO
#   - Una voce per riga (percorso relativo alla radice del progetto).
#   - Voce che finisce con "/"  -> CARTELLA: copiata ricorsivamente, con tutto il contenuto.
#   - Voce senza "/"           -> FILE singolo.
#   - " !div" a fine riga       -> file ad ALTO RISCHIO DI DIVERGENZA: nel "rimanda" serve
#                                  una conferma rinforzata (il runner e il suo avviatore:
#                                  se un progetto li adatta a se', la modifica non deve
#                                  risalire alla madre senza che qualcuno la guardi).
#   - Righe vuote o che iniziano con "#" -> ignorate.
#
# REGOLA D'ORO
#   Qui va SOLO cio' che e' Metodo (condiviso, di proprieta' della madre).
#   MAI file specifici di un progetto: codice, ROADMAP, PROJECT_CONFIG, regole-progetto,
#   docs/ del progetto, diario/decisions.md, diario/ideas.md. Vedi la lista "NON Metodo".
#
# DOVE VIVE IL METODO (riordino del 2026-08-07)
#   .claude/  -> quello che LEGGE l'agente: manuale e skill.
#   metodo/   -> la MACCHINA: runner, strumento di sync, manifest, esempio di config.
#   runner.bat nella radice -> l'unico avviatore che l'umano tocca a mano.
#   Tutto il resto della radice e' del progetto e non si sincronizza mai.
