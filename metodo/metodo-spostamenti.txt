# Spostamenti del Metodo — come i progetti nati prima si riallineano da soli.
#
# A COSA SERVE
#   Il manifest dice DOVE stanno i file del Metodo adesso, e lo scarico li copia
#   la'. Ma un progetto nato prima di un riordino conserva anche le COPIE VECCHIE
#   nei posti vecchi: senza questo file resterebbero doppioni per sempre, perche'
#   lo scarico copia e non cancella mai nulla di sua iniziativa.
#   Qui si dichiara, una volta, "questo era li' e ora sta qua". Lo scarico lo
#   applica e il progetto si trova riordinato senza interventi a mano.
#
# FORMATO
#   tipo | percorso vecchio | percorso nuovo
#
#   tipo = metodo       -> file di PROPRIETA' della madre. Il nuovo arriva con lo
#                          scarico, quindi il vecchio si RIMUOVE. Nessuna perdita:
#                          il contenuto e' della madre, identico per tutti.
#   tipo = impalcatura  -> file il cui CONTENUTO e' del progetto, ma il cui
#                          PERCORSO lo decide il Metodo (il runner li cerca a
#                          percorso fisso). Si SPOSTANO, non si cancellano MAI.
#                          Se esistono sia il vecchio sia il nuovo, non si
#                          indovina: si segnala a Villa e si lascia tutto fermo.
#
#   Percorso nuovo "-"  -> il file non esiste piu' in nessuna forma (solo per
#                          tipo "metodo"; per "impalcatura" e' vietato).
#
# REGOLE
#   - Applicare piu' volte lo stesso spostamento non fa danni (e' idempotente).
#   - Le path escluse da .metodo-sync-ignore vengono saltate anche qui.
#   - Ogni azione viene stampata in chiaro: niente magie silenziose.
